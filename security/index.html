Security at Lemango

Last updated: November 22, 2026

This page summarizes how we approach security for Lemango's website and services. Security is an ongoing process; no website or online service can guarantee that every risk will be prevented.

Current update: We corrected a publishing configuration that had allowed some internal server and debug source files to be served from website paths. In our latest checks, both regular and cache-busted requests to those paths returned 404. We have received a claim that a crawler collected publicly available site resources, but have not independently verified the scope or requests. We have not established whether anyone accessed the files while they were reachable, and our review of provider audit records is not complete. See the Status page for the current summary.

Information and account protections

  • Google sign-in is verified by the backend; Lemango does not receive your Google password.
  • Authenticated sessions use signed, HttpOnly cookies with secure settings in production.
  • Case Manager requests require an authenticated account, and records are restricted to the account that owns them.
  • Browser publishing rules exclude server-side and debug paths from the public static site. Recent checks confirmed that the affected paths return 404.
  • Backend integrations are designed to use deployment environment settings for provider credentials rather than placing those credentials in browser code.

Data handling

Not all information stays on your device. AI prompts are sent to our backend and external AI providers; service logs may contain conversation text and request metadata. Case Manager records are stored on the backend. Some other product preferences and workspace files are stored in your browser. Forge's optional bring-your-own-key settings store user-provided provider keys in browser storage and send them directly to the selected provider. Do not use that feature with a Lemango-owned key or on a shared device. Review our Privacy Policy before submitting information, especially sensitive or confidential information.

Incident update

On November 22, 2026, we identified that some internal source-file paths were accessible through the public website because of a publishing configuration. We corrected the configuration, and the website build containing that correction is deployed. Our latest checks returned 404 for both ordinary and cache-busted requests to the affected paths.

We have not confirmed whether anyone accessed those files. We have not confirmed access to account data, passwords, or credentials; provider audit records have not yet been fully reviewed, so this is not a definitive conclusion. A crawler can download resources that are publicly served; that alone does not establish access to private backend data. We will update the Status page if the investigation establishes additional facts.

Sign-in service

The live backend health check and sign-in session route are responding. We have confirmed that an invalid test credential is rejected; we have not completed an end-to-end Google sign-in test with a valid user account as part of this update.

Payments

Payment processing is not available. Payment-related UI currently shown in FastPay is a demonstration. Lemango does not currently process payments through that feature.

Report a security issue

Email lemangonewsletter@gmail.com with a description, affected page, and steps to reproduce. Please avoid accessing other people's information, disrupting services, or conducting tests beyond what is needed to demonstrate the issue. We ask that you give us a reasonable opportunity to investigate before publishing details. Do not include passwords, tokens, or other secrets in your report.
